# cat-meetup PRD & User Flow

`cat-meetup`은 같은 지역의 고양이 보호자들이 돌봄, 친구찾기, 물품나눔을 안전하게 연결할 수 있도록 돕는 지역 기반 매칭 서비스입니다.
핵심 원칙은 `지역 기반 연결`, `매칭 전 최소 공개`, `후기 기반 신뢰 축적`입니다.

현재 MVP 인증 정책은 `Google 로그인 우선`이며, 로그인 직후 `전화번호를 포함한 기본 프로필 온보딩`을 완료해야만 앱의 주요 기능을 사용할 수 있습니다.

## 1. 서비스 목표

### 해결하려는 문제
- 가까운 지역에서 믿고 맡길 수 있는 고양이 돌봄 상대를 찾기 어렵다.
- 고양이 친구 찾기, 물품 나눔 같은 커뮤니티 수요가 흩어져 있다.
- 연락처를 먼저 공개하면 개인정보 부담이 크다.

### 서비스 목표
- 사용자가 구 단위 지역 필터로 빠르게 게시물을 찾을 수 있어야 한다.
- 매칭 전까지는 개인정보 노출을 최소화해야 한다.
- 매칭 이후 후기와 운영 정책을 통해 신뢰를 쌓을 수 있어야 한다.

## 2. 핵심 사용자

- 신규 가입자: Google 로그인 후 전화번호 포함 기본 프로필을 완성하고 게시물을 탐색하는 사용자
- 게시물 작성자: 게시물을 작성하고 신청자 중 1명을 선택하는 사용자
- 신청자: 게시물에 참여 신청하고, 선택되면 수락 여부를 결정하는 사용자

## 3. MVP 범위

### MVP 포함
- Google 로그인
- 기본 프로필 작성
- 고양이 카드 복수 등록
- 게시물 목록 조회, 상세 조회, 필터링
- 게시물 작성
- 게시물 신청, 선택, 수락
- 상태별 연락처 공개
- 일정 종료 후 후기 작성
- 핵심 알림 이벤트 정의

### 후속 검토 범위
- 포인트/신뢰점수의 사용자 노출 방식
- 앱 내 채팅
- 신고/차단 전용 화면
- 자동 제재 정책 고도화
- 운영자 전용 대시보드

## 4. 공통 정책

### 4.1 회원/프로필 정책
- 로그인은 Google OAuth를 사용한다.
- Google 로그인 직후 기본 프로필 온보딩이 완료되기 전까지는 게시물 목록, 신청, 작성 기능 진입을 제한한다.
- 기본 프로필 필수 항목: 이름, 핸드폰번호, 이메일(구글 계정 기준), 성별, 생년월일, 거주 지역(구 단위), 자기소개
- 카카오톡 ID는 선택 입력 항목으로 시작하되, 연락 수단 보강이 필요할 경우 운영 정책에 따라 필수화할 수 있다.
- 핸드폰번호는 연락/매칭을 위한 필수 프로필 정보이며 중복 가입이 불가하다.
- 거주 지역은 `구` 단위까지만 공개하며 상세 주소는 저장 또는 노출하지 않는다.
- 카카오톡 ID를 입력한 경우 공개 시점은 전화번호와 동일 정책을 따른다.
- 가입 직후 고양이 카드 등록은 선택 사항이다.

### 4.2 고양이 카드 정책
- 한 사용자는 여러 장의 고양이 카드를 만들 수 있다.
- 대표 고양이 카드는 1마리만 지정 가능하다.
- `친구찾기` 게시물 작성 또는 신청 시 대표 고양이 카드 1개 이상이 필요하다.
- `돌봄` 게시물 작성 시 돌봄 대상 고양이 카드 연결이 필요하다.
- `물품나눔`은 고양이 카드 없이도 작성 가능하다.

### 4.3 카테고리별 작성 필수 항목

#### 돌봄
- 제목
- 돌봄 날짜 및 시간
- 예상 소요 시간
- 돌봄 방식: 방문 돌봄 / 물품 전달 / 기타
- 돌봄 대상 고양이
- 특이사항: 급식, 약 복용, 공격성, 분리불안 여부 등
- 본문

#### 친구찾기
- 제목
- 만남 날짜 및 시간
- 보호자 동반 여부
- 대표 고양이 정보
- 중성화 여부
- 건강/주의사항: 전염성 질환, 공격성, 낯가림 등
- 본문

#### 물품나눔
- 제목
- 물품 종류
- 수량
- 상태: 미개봉 / 사용감 있음 / 기타
- 수령 가능 날짜 및 시간
- 전달 방식: 직거래 / 문고리 / 기타
- 본문

### 4.4 게시물/신청 기본 제한
- 사용자는 본인이 작성한 게시물에 신청할 수 없다.
- 동일 사용자는 동일 게시물에 한 번만 신청할 수 있다.
- 일정 시간이 지난 게시물에는 신규 신청할 수 없다.
- 모집 상태가 아닌 게시물에는 신청할 수 없다.
- 작성자는 매칭 완료 전까지만 신청자를 선택하거나 변경할 수 있다.
- 신청자는 `대기중` 상태에서는 신청을 철회할 수 있다.

### 4.5 상태 정의

#### 게시물 상태
| 상태 | 의미 | 허용 액션 |
| --- | --- | --- |
| 모집 | 신청자를 받는 중 | 신청 가능, 작성자 수정/마감 가능 |
| 매칭중 | 작성자가 1명을 선택했고 신청자 수락 대기 중 | 선택 변경 가능, 신청자 수락 가능 |
| 매칭완료 | 신청자가 수락하여 매칭이 확정됨 | 연락처 상호 공개, 후기 대기 |
| 취소(권장 추가) | 작성자 또는 운영 정책에 의해 게시물이 종료됨 | 신규 신청 불가 |
| 일정종료(파생 표시) | 일정 시간이 지나 사용자에게 종료로 보이는 상태 | 읽기 전용 |

#### 신청 상태
| 상태 | 의미 | 허용 액션 |
| --- | --- | --- |
| 대기중 | 신청 완료, 아직 선택되지 않음 | 신청 취소 가능 |
| 매칭중 | 작성자에게 선택되어 수락 대기 중 | 수락 가능, 취소 가능 |
| 매칭완료 | 양측 수락/확정 완료 | 후기 대상이 됨 |
| 실패 | 다른 신청자가 선택되었거나 재선택에서 제외됨 | 읽기 전용 |
| 신청취소(권장 추가) | 신청자가 스스로 철회함 | 읽기 전용 |

### 4.6 상태 전이 규칙
- 게시물은 기본적으로 `모집 -> 매칭중 -> 매칭완료` 순서로 진행된다.
- 작성자가 신청자 1명을 선택하면 선택된 신청은 `매칭중`, 나머지 신청은 `실패`로 변경된다.
- 선택된 신청자가 수락하면 게시물과 신청 모두 `매칭완료`가 된다.
- 작성자는 `매칭완료` 전까지 하루 1회만 재선택할 수 있다.
- 재선택 시 기존에 `실패`였던 신청자 중 1명을 다시 `매칭중`으로 올릴 수 있으며, 이전 선택자는 `실패`로 변경된다.
- `취소`, `신청취소`는 현재 문서 보강을 위한 권장 상태이며 DB/와이어프레임 동기화가 필요하다.

### 4.7 연락처 및 개인정보 공개 정책
| 시점 | 게시물 작성자가 보는 정보 | 신청자가 보는 정보 |
| --- | --- | --- |
| 게시물 열람 전/후 | 공개 프로필, 고양이 카드, 후기 요약만 표시 | 공개 프로필, 고양이 카드, 후기 요약만 표시 |
| 신청 완료 후 `대기중` | 신청자의 연락처 비공개 | 작성자의 연락처 비공개 |
| 작성자가 신청자를 선택해 `매칭중` | 신청자의 연락처 비공개 | 작성자의 핸드폰번호, 카카오톡 ID 공개 |
| 신청자가 수락해 `매칭완료` | 신청자의 핸드폰번호, 카카오톡 ID 공개 | 작성자의 핸드폰번호, 카카오톡 ID 공개 |
| 실패/취소 이후 | 앱 내 추가 공개 없음 | 앱 내 추가 공개 없음 |

### 4.8 후기 정책
- 후기는 `매칭완료` 당사자만 작성할 수 있다.
- 한 게시물에 대해 상대방에게 1회만 작성할 수 있다.
- 양측 모두 서로에게 각각 1개의 후기를 남길 수 있다.
- 후기 작성 가능 시점은 `일정 다음날 00:00` 기준으로 한다.
- 예시: `2026년 1월 28일 19시 30분` 일정이면 후기 작성 가능 시점은 `2026년 1월 29일 00시 00분`이다.
- 후기 작성 가능 기간은 14일로 권장한다.
- MVP에서는 후기 작성 후 수정/삭제를 지원하지 않는다.

### 4.9 취소/노쇼/신고 정책
- `대기중` 상태 신청 취소는 자유롭게 허용한다.
- `매칭중` 이후 취소 시 취소 사유 입력을 필수로 한다.
- `매칭완료` 이후 취소 시 상대방에게 즉시 알림을 보내고 운영 기록을 남긴다.
- 반복 취소, 노쇼, 신고 확정은 추후 신뢰점수 또는 이용 제한 정책과 연결한다.
- MVP에서는 앱 내 신고 화면이 없어도 운영 문의 채널은 반드시 제공한다.

### 4.10 알림 정책
- 새 신청이 들어오면 게시물 작성자에게 알림
- 신청자가 선택되면 해당 신청자에게 알림
- 신청자가 수락하면 게시물 작성자에게 알림
- 일정 하루 전 양측에게 리마인드 알림
- 후기 작성 가능 시점에 양측에게 알림

### 4.11 운영 지표
- 회원가입 완료율
- 게시물 작성 수
- 신청 전환율
- 매칭 완료율
- 후기 작성률
- 취소율 및 노쇼 비율
- 지역별, 카테고리별 수요/공급 불균형

## 5. 사용자 흐름

### 5.1 신규 가입자
1. 앱 실행
2. Google 로그인
3. 기본 프로필 온보딩
   - 이름
   - 핸드폰번호(필수)
   - 카카오톡 ID(선택)
   - 이메일(구글 계정)
   - 성별
   - 생년월일
   - 사는 지역(구 단위)
   - 본인 설명/자기소개
4. 동물 등록 여부 선택
   - 지금 등록
   - 나중에 등록
5. 동물 카드 작성(복수 생성 가능)
   - 고양이 이름
   - 고양이 성별
   - 고양이 나이
   - 중성화 여부
   - 고양이 성격
   - 고양이 사진
   - 고양이 설명
6. 매칭 게시물 목록 조회
   - 지역 기반 조회(구로구/관악구/노원구 등)
   - 카테고리 조회(돌봄/친구찾기/물품나눔)
7. 게시물 클릭 후 내용 확인
   - 제목
   - 카테고리
   - 일시
   - 본문
   - 작성자 공개 프로필
   - 고양이 정보
   - 후기 요약
8. 신청 가능한 게시물일 경우 참여 신청
9. 신청 완료 후 버튼 비활성화, 상태는 `대기중`으로 표시
10. 신청한 게시물 목록에서 상태 확인
   - `대기중`
   - `매칭중`
   - `매칭완료`
   - `실패`
11. `매칭완료` 후 상대 연락처 확인
12. 일정 종료 다음날부터 후기 작성 가능

### 5.2 회원: 게시물 작성자
1. 앱 실행
2. 매칭 게시물 목록 진입
   - 지역/카테고리/상태 필터 사용 가능
3. 새 글 작성 버튼 선택
4. 게시물 작성
   - 제목
   - 카테고리
   - 날짜/시간
   - 카테고리별 필수 입력값
   - 본문
5. 게시물 등록 완료 후 상세 화면 진입
6. 신청자 목록 확인
   - 사람 프로필
   - 고양이 정보
   - 후기 내용
7. 신청자 1명 선택
   - 선택된 사람 상태: `매칭중`
   - 선택되지 않은 사람 상태: `실패`
8. 선택된 신청자에게만 작성자 연락처 공개
9. 신청자가 수락하면 게시물 상태 `매칭완료`
10. `매칭완료` 이후에는 작성자도 신청자 연락처 확인 가능
11. 일정 종료 후 후기 작성

### 5.3 회원: 신청자
1. 앱 실행
2. 매칭 게시물 목록 조회
   - 지역 기반 조회
   - 카테고리 조회
   - 게시물 상태 조회
3. `모집` 상태 게시물 선택
4. 게시물 내용, 작성자 프로필, 고양이 정보, 후기 확인
5. 신청 버튼 선택
6. 신청 완료 후 상태 `대기중` 표시
7. 신청한 게시물 목록 조회
8. 선택된 경우 매칭 목록에서 `매칭중` 상태 확인
9. 작성자 연락처 확인 후 수락 여부 결정
10. 수락 시 상태 `매칭완료`
11. 서로 연락 후 일정 진행
12. 일정 종료 다음날부터 후기 작성

## 6. 화면/개발 연동 메모

- 게시물 상세 화면에는 단순 본문 외에 카테고리별 필수 항목 노출이 필요하다.
- 후기 가능 시점 계산은 한국 시간대 기준 `다음날 00:00`으로 처리하는 것이 사용자 기대와 맞다.
- 연락처 공개 규칙은 PRD, 와이어프레임, 타입, DB 스키마에서 동일해야 한다.
- `취소`, `신청취소`, `일정종료` 상태를 저장값으로 둘지 파생 표시로 둘지 설계 확정이 필요하다.
- 친구찾기 카테고리는 안전상 건강 정보, 보호자 동반 여부, 공격성 안내가 특히 중요하다.

## 7. 추후 확정 필요 항목

- 실명만 쓸지, 앱에서 보여줄 별도 표시명(display name)을 둘지
- 신뢰점수와 포인트를 MVP에 내부 운영 지표로만 둘지, 사용자에게도 노출할지
- 신고/차단 기능을 MVP에 포함할지, 운영 채널로 먼저 대체할지
- 친구찾기 카테고리에서 오프라인 만남 허용 범위와 안전 가이드를 어디까지 강제할지
